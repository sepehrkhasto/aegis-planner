# Aegis 3 — نقشهٔ راه کامل

وضعیت: در حال اجرا · شاخه: `v3` · مرجع: Aegis Planner 2.11.10 (پایتون، در `legacy/`)
برچسب‌ها: ✅ انجام‌شده · 🔄 در جریان · ⬜ مانده. کد `[D..]`/`[A..]` یعنی این فاز کدام ایراد یا کار فهرست قبلی (`aegis-roadmap-fa.txt`) را رفع می‌کند.

## چشم‌انداز

Aegis یک **هستهٔ باز، امن و آفلاین برای برنامه‌ریزی شخصی** است. مثل لینوکس، هسته کار حساس را انجام می‌دهد و ابزارها روی آن سوار می‌شوند:

```
  فضای کاربر:   برنامهٔ گرافیکی رسمی · ابزار خط فرمان aegis · TUI · رابط‌های دیگران (GTK, Qt, KDE...) · اسکریپت‌ها
                       │                    │                         │
  درگاه‌ها:      Rust API (aegis-core) · C ABI (libaegis + aegis.h) · CLI با خروجی JSON · aegisd (اختیاری)
                       │
  هسته:          رمزنگاری · فرمت فایل · مدل داده · منطق · ذخیره‌سازی · همگام‌سازی   (Rust، بدون unsafe)
```

اصول:
1. **هسته یک بار نوشته می‌شود** و همهٔ برنامه‌ها، رسمی یا غیررسمی، از آن استفاده می‌کنند.
2. **«فضای کاربر را نمی‌شکنیم».** API، ABI، خروجی JSON و فرمت فایل نسخه‌بندی معنایی دارند. تغییرِ شکننده فقط با RFC، دورهٔ منسوخ‌سازی و نسخهٔ اصلی جدید انجام می‌شود.
3. **نسخهٔ پایتون داور است.** هر رفتار 2.x با بردار تست سنجیده می‌شود، مگر آنچه آگاهانه عوض شده (جدول آخر سند).
4. **هیچ ولتی از دست نمی‌رود.** نسخهٔ 3 همهٔ فایل‌های 2.x و وب را برای همیشه می‌خواند.
5. **امنیت بر راحتی مقدم است.** افزونه‌ها هرگز داخل فرایند هسته اجرا نمی‌شوند و کلیدها هرگز از هسته بیرون نمی‌روند.
6. **لینوکس شهروند درجه یک است.** ویندوز و لینوکس از روز اول، اندروید بعد از 3.0.
7. **هر فاز کوچک است و شرط پایان دارد.** هر فاز یک یا چند commit است.

## ریپو و شاخه‌ها

- همین ریپو ادامه پیدا می‌کند تا ستاره‌ها، دانلودها و کاربران سر جایشان بمانند.
- `main` فعلاً 2.x است و اصلاحیه‌های امنیتی آن نسخه آنجا منتشر می‌شوند. کار جدید روی `v3` است.
- با انتشار 3.0، شاخهٔ `legacy/2.x` از `main` ساخته می‌شود، `v3` در `main` ادغام می‌شود و پوشهٔ `legacy/` حذف می‌شود.

## چیزهایی که آگاهانه عوض می‌شوند

| در 2.x | در 3 | چرا |
|---|---|---|
| انیمیشن‌های ورود (overture، ذرات، cinema) | حذف | سرعت و سادگی |
| یک برنامهٔ یکپارچه | هسته + درگاه‌ها + ابزارهای جدا | توسعه‌پذیری، مثل لینوکس |
| `normalize()` کلیدهای `passwords`/`plans` را حذف می‌کند | حفظ همهٔ فیلدهای ناشناخته | از دست رفتن داده |
| هدر احراز هویت نمی‌شود | AAD در v2 | rollback و دست‌کاری |
| فقط PBKDF2 | Argon2id (v2)؛ PBKDF2 فقط برای خواندن v1 | مقاومت در برابر GPU |
| ذخیره بدون بررسی تداخل | بررسی revision | بازنویسی بی‌صدا |
| تکرار با کپی‌های مستقل | قاعده + استثنا | ویرایش سری |
| ادغام فقط آیتم جدید | ادغام کامل سطح آیتم | همگام‌سازی |
| فقط ویندوز، فقط فارسی | ویندوز + لینوکس، فارسی + انگلیسی | جامعهٔ بزرگ‌تر |
